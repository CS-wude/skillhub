# 制作与技术质检

## 预算与工具

检查真实磁盘空间，估算配音、片段、成片、压缩包、临时文件与交付副本的峰值。空间不足先调整缓存与渲染策略，用户文件清理需明确授权。

免费路线按需要选择：二维关系与精确文字用 HTML/CSS/SVG；空间模型、材质与骨骼用 Three.js；需要真实软件行为时用已有应用工程；配音用可用免费 TTS 或已有本地 TTS；编码合成用 FFmpeg/ffprobe。先发现已有工具，再安装小型隔离依赖。固定版本并保存必要许可证。在线接口可用性与免费条件需要核对。

推荐工程保留 script、src、assets、audio、segments、review、delivery。可执行路径通过配置或环境变量传入，不能依赖另一个待清理课程的虚拟环境或 node_modules。工程压缩包须有重建命令、依赖版本、必要资产和服务限制。

## 配音、字幕与时间线

1. 先试术语、英文缩写、数字和代码读法，再批量生成。口播发音变体与屏幕拼写分开管理。
2. 缓存键包含文本、音色、语速和工具版本，改变内容或参数刷新对应语音。
3. 读取真实时长与词边界，归一化边界文本并核对是否覆盖口播。
4. 字幕按语义、阅读速度与中英文差异断行，通常最多两行；时间非负、单调、起点小于终点且不超出成片。
5. 无可靠词边界时使用强制对齐或 ASR 辅助并复核。ASR 易误认术语和数字，不能直接替换原稿。
6. 前后留少量自然余量并转成整帧，总时长用片段帧数累加；镜头事件按语音锚点定位。

## 渲染与合成

技术短测覆盖中文字体、三维、透明度、字幕与声音。长片分段渲染，动画由固定输入时间驱动，随机状态设种子。字体与场景初始化完成再截图。

用独立无头浏览器，帧通过管道送编码器以减少磁盘占用。并发按内存与持续吞吐决定。每段检查返回值、帧数、时长，缓存键包含脚本、场景、资源与渲染参数。

知识课可从 1920×1080、30 fps、H.264/yuv420p + AAC、faststart 起步。最终混音约 -16 LUFS、真峰值不高于 -1.5 dBTP 可作初始目标，仍需监听。不要为追求参数牺牲清晰度或产生失真。

可烧录字幕并附 SRT，可选字幕需验证目标播放器。章节封装出现无效 QT chapter 引用等警告时修复再复检；必要时交付外部导航并准确说明。

## 最终验收

工具只做部分检查：

```sh
python3 scripts/check_delivery.py /absolute/path/to/delivery --ffprobe /path/to/ffprobe
```

默认只读并输出 JSON，`--write-manifest` 才生成根目录 SHA256SUMS.txt。工程 ZIP 和成片都放在交付目录内。

完整解码示例：

```sh
ffmpeg -v error -xerror -i final.mp4 -map 0:v:0 -map '0:a:0?' -f null -
```

核对 stderr 与退出码。重编码或改封装后重新完整解码及计算哈希。媒体探测不能证明整片可解码。

每段至少三处实际编码抽帧，另查文字密集处、转场、比较镜头与运动接触点；不能仅看渲染器预览。监听术语、数字、拼接、开头与结尾。自动 ASR 只作诊断，不能等同于完整人工审听。

ZIP 完整性之外，尽量在临时目录干净重建代表片段，记录是否进行完整重建。区分脚本通过、ZIP 可解压、完整解码、视觉抽查与整片人工审查。

# 成片检查与交付

## 把抽查安排在容易出错的地方

先检查原始渲染，再对最终 MP4 解码抽帧。逐镜抽查开头、动作或中段、结尾；再补查事件前后、场景切换、复杂遮挡和道具交接。不只凭联系表的小图确认手部接触，关键处放大看编码后的原尺寸帧。

| 范围 | 需要看到的证据 |
| --- | --- |
| 故事 | 规则展示与实际使用一致，选择有代价，结尾回收已建立的信息 |
| 连续性 | 道具无重复、状态不复活、人物身份明确、时段可辨、门后可通行 |
| 表演 | 手摸到物体、抱人有支撑、物品不漂浮、腿不穿墙、脚不明显滑地 |
| 镜头 | 重要动作在画幅内、视线与目标关系清楚、字幕不挡动作 |
| 字幕 | 全文匹配批准稿、重复词无错位、短句自然、时间有序且不越界 |
| 声音 | 关键词发音、音效锚点、拼接、开头和结尾、异常静音、配乐遮盖旁白 |

如果没有完整人工监听，记录未做；音量检测和 ASR 不能冒充监听。修字幕要更新烧录画面，外置 SRT 改对了不能视为视频里的字幕也已修正。

## 媒体完整性

记录实际时长、帧率、帧数、分辨率、编码和音轨。检查整个最终文件：

```sh
ffmpeg -v error -xerror -i final.mp4 -map 0:v:0 -map '0:a:0?' -progress pipe:1 -f null -
```

核对退出码、stderr、最终帧数与时间线；ffprobe 能解析头部不代表完整解码通过。改字幕、画面、音轨或封装后重检最终媒体。

随包的 `scripts/check_delivery.py` 检查 ZIP、哈希和可用的 ffprobe 元数据；它不会完整解码、看画面或听声音。执行时替换为技能真实绝对路径：

```sh
python3 /absolute/path/to/wude-story-video/scripts/check_delivery.py /path/to/delivery --write-manifest
python3 /absolute/path/to/wude-story-video/scripts/check_delivery.py /path/to/delivery --verify-manifest
```

最终交付目录改变后重新生成清单；报告不要写进正在校验的目录里造成清单自我变化。没有 ffprobe 时记录缺失，并使用实际编码器输出等证据核对媒体参数，不能宣称脚本已检查元数据。

校验器单独报告并忽略 Finder 自动生成的 `.DS_Store`；成片、脚本、音频、工程包及其他实际文件仍全部参加清单核对。此例外不能推广成忽略所有隐藏文件。

## 交付组成

- 成片 MP4、可用封面、SRT、完整口播与分镜。
- 简短制作说明：故事设定、关键连续性、工具及依赖版本、重建命令、字体与服务限制。
- 可编辑工程 ZIP：源码、时间线、已生成的配音、必要素材和许可证、依赖锁文件。不把用户凭据、node_modules、虚拟环境或可重建的大量中间帧装进去。
- 检查记录和 SHA256SUMS；记录自动检查、实际视觉抽查、监听覆盖、是否进行工程重建。压缩包完整性和干净环境能重建是两项不同的检查。

重要的可重复逻辑进技能，单片故事和资产留工程。后续新增经验以实际失误或有效改进为依据，不把每片特殊做法累积成所有视频必须遵守的模板。

普通交付停在本地成片与目录。用户另行要求归档、网盘或清理时，按本次明确范围继续；归档记录保留原稿、成片与重建材料，清理前确认对应授权和备份情况，不沿用别的目录的删除授权。

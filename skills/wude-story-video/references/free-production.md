# 免费制作与时间线

## 工具与工程

先发现已有工具及可用磁盘。程序化建模、关节动画、相机和材质可用 Three.js；排版与精确文字用 HTML/CSS；逐帧截图用独立无头浏览器；编码混音用 FFmpeg；语音用可用免费接口或本地 TTS；音效和配乐可程序合成。确需复杂建模、模拟时才选择已有 Blender 等工具，不为了叙事动画先安装大型编辑器。

已验证的一组组合是 Three.js r160、puppeteer-core 25.17.0、edge-tts 7.3.1、Pillow 13.0.0。它们是历史可复用版本，不是当前最新版或永久免费承诺；新工程核对运行环境，选择兼容版本并锁定。免费在线语音接口可能失效，保留已生成音频；不能称为永久免费服务。

建议每片保留 `script/`、`src/`、`assets/`、`audio/`、`segments/`、`review/` 和 `delivery/`。依赖在本工程隔离，工具路径通过 `FFMPEG`、`FFPROBE`、`CHROME_PATH` 等配置传入；交付副本不依赖另一待清理项目的工具。保留依赖锁文件、必要许可证与字体要求。

在批量制作前做小型技术短测：中文字体、三维灯光、字幕、安全区、音频编码和实际输出尺寸。检查中间文件、成片、工程包及交付副本同时存在时的峰值空间。不要擅自清理用户历史文件。

## 时间线与字幕

1. 从批准口播生成语音，先核对人名、数字和关键音效词。语音缓存指纹包含文本、声音、语速和生成参数。
2. 测量真实音频时长并读取词边界。使用明确的段首静音和段尾余量，统一到整帧。片段起点由前面片段帧数累加，不分别四舍五入全局起点。
3. 逐词归一化内容并核对顺序。字幕短句先按语义编写，再用顺序游标消耗词边界；不要拿每组最后一个词到原文 `find()`，重复的“有人”“把”“门”等会匹配到前一次出现，造成字幕内容和时间错配。
4. 字幕短句边界与语音 token 边界一致。确需拆开一个 token 时应重新分句或使用可靠的更细对齐，不能编造逐字时间。检查阅读速度、断行和过短提示，必要时在不重叠前提下延长停留。
5. 事件使用命名锚点，锚点记载词或短语以及出现序号，避免字典同名键覆盖。按下、解锁、光消失和铃声共用同一事件，先后有意错开时写明偏移。
6. 保持原稿为文字事实源，ASR 仅辅助诊断漏读与发音。没有可靠边界时用强制对齐或人工复核，不能平均分配每字时间然后称为实测。

### 字幕助手

`scripts/align_subtitles.py` 仅用 Python 标准库。输入 JSON 的相对词边界路径以该 JSON 所在目录解析；Edge 风格词边界 offset/duration 单位是 100 ns。时间线的 start/duration 单位是秒，已经包含段首静音。输入示例：

```json
{
  "fps": 30,
  "scenes": [{
    "id": "S01",
    "text": "叮。门锁开了。",
    "phrases": ["叮。", "门锁开了。"],
    "start": 0,
    "duration": 4,
    "voice_delay": 0.18,
    "words_file": "audio/S01.jsonl",
    "events": [{"id": "unlock", "text": "叮", "occurrence": 1, "delta": 0}]
  }]
}
```

```sh
python3 /absolute/path/to/wude-story-video/scripts/align_subtitles.py timeline-input.json --out-dir timeline
```

输出 `字幕.srt` 与 `aligned.json`，后者含字幕和事件的全局秒数。助手核对全文、重复词、顺序、片段范围和整帧边界；不代替字幕语义、发音及可读性检查。事件短语需从真实 token 起点开始。若带偏移，检查事件仍位于片段内。

## 确定性渲染

动画由输入时间求值，固定随机种子。用绝对时间计算关节角度、位移和相机，不能依赖上一帧积分或墙钟。段落状态从统一状态表初始化；跳到任意镜头不应依赖之前看过哪些镜头。

等待字体、纹理与场景加载完成后截图。浏览器使用独立无头实例，避免干扰用户正在操作的浏览器。帧通过管道写入编码器并处理背压，减少保存数千张 PNG 的空间；并发由实际吞吐和内存决定。

渲染先写临时文件，检查进程返回、帧数与媒体可解码性后，再改名为有效缓存并写入输入指纹。指纹包含口播、字幕、场景代码、资产、事件与渲染参数；中断留下的 MP4 或零退出码之外的错误不能被“已存在”跳过。长片逐段缓存，局部修改只重做受影响部分及合成。

可从 H.264、yuv420p、AAC 48 kHz、30 fps、faststart 起步，按用途调整。先统一每段精确时长再拼接、混音；不要依靠 `-shortest` 掩盖时间线错误。音轨可包含旁白、低音量配乐、事件音效；铃声等音效按事件表定位。约 -16 LUFS、真峰值 -1.5 dBTP 是起始目标，AAC 可能改变峰值，检查最终编码而非只看混音参数。
